# WikiMasters Automation

Python + Playwright automation for a WikiMasters account.

The repo currently has four separate workflows:

- open available card packs from `/pulls`;
- summarize recently opened cards;
- classify and tag collection cards from `/collection`;
- auction cards tagged `à bicrave`.

All browser scripts use normal authenticated WikiMasters UI interactions. They load credentials from `.env` locally or from GitHub Actions secrets in CI. Dry run is the default for scripts that can mutate collection tags or auctions.

## Project Structure

```text
.
├── .github/workflows/
│   ├── opened-cards-summary.yml
│   ├── open-wikimasters-packs.yml
│   ├── sell-shitty-cards.yml
│   └── tag-collection-cards.yml
├── scripts/
│   ├── env_loader.py
│   ├── open_packs.py
│   ├── tag_collection_cards.py
│   └── sell_shitty_cards.py
├── tests/
│   └── test_topic_classifier.py
├── .env.example
├── requirements.txt
└── README.md
```

- `scripts/open_packs.py`: opens available packs and records revealed cards.
- `scripts/tag_collection_cards.py`: scans the collection, classifies cards, writes reports, and can apply étiquettes.
- `scripts/sell_shitty_cards.py`: sells cards tagged `à bicrave` in auction batches.
- `scripts/env_loader.py`: loads local `.env` values without overriding existing environment variables.
- `tests/test_topic_classifier.py`: pure tests for classifiers, saved candidates, result parsing, and pricing logic.
- `artifacts/`: local generated reports, caches, screenshots, and failure metadata. This directory is ignored by git.

## Setup

Create a virtual environment and install dependencies:

```bash
python3 -m venv .venv
. .venv/bin/activate
python3 -m pip install -r requirements.txt
python3 -m playwright install chromium
```

Create `.env` from `.env.example`:

```dotenv
WIKIMASTERS_EMAIL=you@example.com
WIKIMASTERS_PASSWORD=replace-with-your-password
HEADLESS=1
```

Set `HEADLESS=0` when you want to watch the browser locally.

## Common Workflows

### Open Packs

Open packs locally:

```bash
python3 scripts/open_packs.py
```

The GitHub workflow `.github/workflows/open-wikimasters-packs.yml` runs this script in CI.

### Dry Run Tags

Dry run is the default. It scans the collection once, uses cached Wikipedia metadata, writes a report, and saves reusable candidates:

```bash
python3 scripts/tag_collection_cards.py
```

Useful focused dry runs:

```bash
python3 scripts/tag_collection_cards.py --tags plante
python3 scripts/tag_collection_cards.py --tags rivière
python3 scripts/tag_collection_cards.py --tags philo,scam --sample-per-tag 10
python3 scripts/tag_collection_cards.py --tags "à bicrave"
```

Inspect the report:

```bash
less artifacts/tag_report.md
```

### Apply Tags

The tagger only adds new tags to cards that currently have no tags. If a no-tag card matches multiple enabled classifiers, it is assigned to the first matching enabled tag.

Apply from the saved candidates generated by the latest dry run. This avoids rescanning the whole collection:

```bash
python3 scripts/tag_collection_cards.py --apply-candidates --tags plante --batch-size 1
python3 scripts/tag_collection_cards.py --apply-candidates --tags "à bicrave" --batch-size 1
```

For a one-card live smoke test:

```bash
python3 scripts/tag_collection_cards.py --apply-candidates --tags "à bicrave" --batch-size 1 --max-apply-candidates 1
```

To force a fresh scan and apply in one command:

```bash
python3 scripts/tag_collection_cards.py --apply --tags plante --batch-size 1
```

Apply all topic tags except `à bicrave`:

```bash
python3 scripts/tag_collection_cards.py --apply --exclude-tags "à bicrave" --batch-size 1
```

Audit existing tags and report cards whose current tag no longer matches the classifier:

```bash
python3 scripts/tag_collection_cards.py --dry-run --tags plante --audit-existing --sample-per-tag 0
```

Remove invalid existing tags after an audit. This uses each card detail's tag remove button and verifies the tag is gone:

```bash
python3 scripts/tag_collection_cards.py --remove-invalid-existing --tags plante --batch-size 1
```

### Sell `à bicrave` Cards

The `à bicrave` tag is used to tag and sell shitty cards.

Full local flow: scan the collection, apply strict `à bicrave` candidates, then launch auctions on all shitty cards:

```bash
python3 scripts/tag_collection_cards.py --apply --tags "à bicrave" --batch-size 1 && \
python3 scripts/sell_shitty_cards.py --apply
```

Seller dry run:

```bash
python3 scripts/sell_shitty_cards.py
```

Launch one batch of up to 5 auctions:

```bash
python3 scripts/sell_shitty_cards.py --apply --cycles 1
```

Run repeated batches. The script launches up to 5 auctions, waits 10 minutes and 10 seconds, then tries the next batch:

```bash
python3 scripts/sell_shitty_cards.py --apply
```

By default the seller scans all cards returned by the `à bicrave` filter each cycle. Use `--scan-limit N` only when you intentionally want to inspect the first `N` filtered cards.
Before launching an auction, the seller opens the card detail and verifies that the card itself shows the `à bicrave` tag.

Unsold cards keep their `à bicrave` tag. The seller records a retry pass in `artifacts/sell_auction_state.json`:
every visible tagged card gets one auction attempt before previously attempted unsold cards are eligible again,
even across separate script runs.

Do not run mutating tag and seller commands in parallel. Dry runs are fine, but `--apply` tag runs can change the same filtered collection that the seller is reading.

The GitHub workflow `.github/workflows/sell-shitty-cards.yml` runs this seller flow on the self-hosted WikiMasters runner. It sells currently tagged `à bicrave` cards, applies only the `à bicrave` tag when the visible tagged pool is empty, then sells again. The workflow is manual-only and stops after 24 hours, or earlier if the tagger finds no new `à bicrave` candidates.

The GitHub workflow `.github/workflows/tag-collection-cards.yml` runs manually on the self-hosted WikiMasters runner and applies all supported tags except `à bicrave` to all matching untagged cards by default. Set `max_apply_candidates` to a positive number for a bounded run. Its workflow summary lists the non-`à bicrave` cards tagged during the run, grouped by tag with rarity emoji.

## Tagging Rules

Supported tags:

- `plante`: actual plant taxa only.
- `philo`: core philosophy people, schools, concepts, works, arguments, and institutions.
- `scam`: central scams, fraud cases, Ponzi schemes, fraudsters, and fraudulent organizations.
- `train`: train objects only, such as trains, locomotives, rolling stock, types, classes, and models.
- `rivière`: watercourses, canals, and wetlands, such as rivers, fleuves, streams, torrents, tributaries, canals, marshes, and Ramsar sites.
- `souterrains`: underground structures and places, such as caves, tunnels, mines, catacombs, bunkers, and underground complexes.
- `à bicrave`: low-rarity untagged cards to sell.

Automated `à bicrave` tagging is deliberately strict. The tagger only applies it when all conditions are true:

- the card has no other existing tag;
- rarity is `C` or `PC`;
- the card is a village/town, political person, TV show, movie, sport athlete, or pornographic topic.

There is also an apply-time guard: if a saved candidate file contains any non-`C`/`PC` card for `à bicrave`, the tagger refuses to mutate.

The seller has a separate rule for manually tagged cards:

- `C` and `PC` `à bicrave` cards start at `10`;
- manually tagged `R`, `SR`, and `UR` `à bicrave` cards still sell, but start at `40`;
- `L` cards are never auctioned by the seller, even if they carry `à bicrave`.

## Generated Files

The tagger writes:

- `artifacts/tag_report.md`: human-readable report grouped by tag.
- `artifacts/tag_candidates.json`: reusable candidates for `--apply-candidates`.
- `artifacts/wikimasters_wikipedia_cache.json`: cached Wikipedia metadata.

Failure screenshots and metadata are also written under `artifacts/`.

The seller also writes `artifacts/sell_auction_state.json` to remember the current `à bicrave` retry pass.

## Configuration

Environment variables:

- `WIKIMASTERS_EMAIL`: required login email.
- `WIKIMASTERS_PASSWORD`: required login password.
- `HEADLESS`: defaults to `1`; use `0` to show the browser.
- `ARTIFACT_DIR`: defaults to `artifacts`.
- `WIKIMASTERS_UI_JITTER_MS`: defaults to `80`; maximum tiny random UI pause added after scripted actions.

Pack opener environment variables:

- `MAX_PACKS_PER_RUN`: defaults to `10`.
- `MAX_CARD_ADVANCES`: defaults to `20`.
- `PACK_OPEN_MAX_WAIT_MS`: defaults to `5000`.
- `CARD_ADVANCE_DELAY_MS`: defaults to `350`.
- `CARD_DETAILS_MAX_WAIT_MS`: defaults to `1200`.
- `RIGHT_ARROW_ROLE_TIMEOUT_MS`: defaults to `100`.

Tagger options:

- `--dry-run`: default; report candidates without changing tags.
- `--apply`: scan and apply matching tags through the bulk UI for cards with no existing tags.
- `--apply-candidates`: apply tags from `artifacts/tag_candidates.json` without a full rescan; already-tagged saved candidates are skipped.
- `--audit-existing`: include already-tagged cards in the report and show tags that no longer match.
- `--remove-invalid-existing`: remove already-applied tags that fail the classifier. Requires explicit `--tags`.
- `--tags`: comma-separated supported tags. Defaults to all supported tags.
- `--exclude-tags`: comma-separated supported tags to exclude from the enabled tag set.
- `--sample-per-tag`: defaults to `10`; use `0` to show all candidates in the report.
- `--max-cards`: defaults to `0`, meaning all collection cards.
- `--batch-size`: defaults to `8`; `1` is safer for live tagging.
- `--max-apply-candidates`: defaults to `0`, meaning all candidates.
- `--scroll-delay-ms`, `--selection-delay-ms`, `--batch-delay-ms`, `--wikipedia-delay-ms`: throttling controls.
- `--jitter-ms`: defaults to `80`; use `0` to disable.
- `--cache-path`, `--report-path`, `--candidate-path`: override artifact paths.

Seller options:

- `--dry-run`: default; report auctions without launching them.
- `--apply`: launch auctions through the WikiMasters UI.
- `--tag`: defaults to `à bicrave`.
- `--max-cards-per-cycle`: defaults to `5`, and cannot exceed `5`.
- `--scan-limit`: defaults to `0`, meaning all tagged cards scanned per cycle.
- `--cycles`: defaults to `0`, meaning repeat until no visible tagged cards are available.
- `--wait-seconds`: defaults to `610`.
- `--start-price`: defaults to `10` for `C`/`PC` cards.
- `--non-low-rarity-start-price`: defaults to `40` for manually tagged `R`, `SR`, and `UR` cards.
- `--duration`: defaults to `10 min`.
- `--jitter-ms`: defaults to `80`; use `0` to disable.
- `--state-path`: defaults to `artifacts/sell_auction_state.json`.

## GitHub Actions And cron-job.org

The GitHub workflows can open packs, tag collection cards, summarize opened cards, and run the `à bicrave` seller loop.

Add repository secrets:

```bash
gh secret set WIKIMASTERS_EMAIL
gh secret set WIKIMASTERS_PASSWORD
```

Trigger manually:

```bash
gh workflow run open-wikimasters-packs.yml --ref main
gh workflow run tag-collection-cards.yml --ref main
gh workflow run sell-shitty-cards.yml --ref main
```

cron-job.org can call the workflow dispatch endpoint:

```text
POST https://api.github.com/repos/OWNER/REPO/actions/workflows/open-wikimasters-packs.yml/dispatches
```

Headers:

```text
Authorization: Bearer <YOUR_FINE_GRAINED_GITHUB_TOKEN>
Accept: application/vnd.github+json
X-GitHub-Api-Version: 2026-03-10
Content-Type: application/json
User-Agent: wikimasters-cron-job
```

Body:

```json
{"ref":"main"}
```

Use a fine-grained token scoped only to this repository with `Actions: Read and write`.

Failure artifacts are uploaded only while the repository is private, because screenshots and page metadata may include authenticated WikiMasters account state.

## Troubleshooting

- **`python: command not found`**: use `python3`, or activate `.venv`.
- **Playwright browser missing**: run `python3 -m playwright install chromium`.
- **Login fails**: verify `.env`, CAPTCHA, 2FA, or email verification.
- **No cards found by seller**: run a tagger dry run/apply first, then check the `à bicrave` filter in WikiMasters.
- **Card disappears while selling**: the seller recollects and skips unavailable cards; rerun after active auctions expire.
- **UI changed on WikiMasters**: inspect the latest screenshot and metadata under `artifacts/`.
- **GitHub workflow does not appear**: make sure the workflow file under `.github/workflows/` is committed and pushed.

## Security Notes

- Never commit `.env` files or real credentials.
- Use GitHub repository secrets for CI credentials.
- Store the cron-job.org GitHub token only in cron-job.org.
- Use a fine-grained GitHub token with only `Actions: Read and write` on this repository.
- Rotate the cron-job.org token and WikiMasters password if either is exposed.
- Do not publish local ignored files such as `.env`, `.venv/`, `.vscode/`, or `artifacts/`.
